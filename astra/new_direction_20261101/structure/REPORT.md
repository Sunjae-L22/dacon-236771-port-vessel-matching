# 어휘·언어·이름 구조 방향 검토

결론: **현재 검증한 독립 어휘 구조 방향은 기각한다.** 기존 모델과 다른 좁은 가설을 실제 한글 이름으로 실험했지만 추가 target coverage가 0이었다. 이를 0.98 후보라고 포장할 근거가 없다. GPU, Public 제출, KoCat 표 교체, noisy-channel 실험은 하지 않았다.

## 실제 기존 코드와 겹치는 부분

- `external/ksh/src/name_token_prior.py`: 첫/마지막 토큰의 학습 선박 출현률, 카탈로그 대비 population prior, flag/type/joint lift를 계산하는 **이전 실험 코드**이다. 동결 C_vote v20에서 활성화되었다는 근거는 없다. 적어도 서로 다른 학습 선박 세 척이 공유하는 토큰에만 적용한다. `external/ksh/docs/nested_combiner_20261029.md:51`의 실험 기록은 v12 대비 anchor −0.000948, bootstrap CI [−0.006549, +0.004556], testlike +18/−20, 단어 생략 한글 .846501→.828442로 기각되었다고 명시한다. 따라서 단순 fleet-prefix prior는 새 방향이 아니라 이전 기각 실험의 반복이다.
- `astra/arena_20261101/baseline/model/hs/model/matcher.py`: 문자 TF-IDF, token blocking, FastSS 인덱스, 이니셜 및 붙은 약자 분해, 단어 순서 교환, 알려진 한글 단어를 번역한 뒤의 token blocking을 이미 사용한다.
- `shared/src/ko_translit_argon.py`: 해운사 접미사·의미 번역, 실제 학습 쌍에서 얻은 단어/DP subword 사전, 토큰별 커버리지, 모든 토큰 인덱스가 있다.
- HSW graphone과 단순 발음 모델 재학습, 이미 보류된 음절 오류 채널은 이번 실험에서 사용하지 않았다.

## 다르게 검증한 가설

기존 사전이 한글 토큰마다 최빈 영어 번역 하나를 선택할 때 버리는 대안을 모두 유지하고, **카탈로그에 실제 존재하는 전체 토큰 조합**으로 문맥적 모호성을 풀 수 있는가?

이는 first/last token의 population prior와 다르다. 행의 실제 토큰들이 함께 성립하는 이름을 찾으며, 모든 후보를 이미 읽은 신경망의 출력에 의존하지 않는다. 별도 학습한 사전만 쓰므로 기존 v20/112가 train 전체를 보았다는 평가 편향을 이 작은 실험에서는 피한다. 다만 C_vote와 비교한 것은 아니다.

## 사전 고정한 CPU 실험

실행: `PYTHONDONTWRITEBYTECODE=1 python3 astra/new_direction_20261101/structure/lexical_lattice_probe.py`

- 실제 train 한글 1,191행을 사용한다. 합성 질의와 KoCat 별칭은 사용하지 않는다.
- 선박 ID 해시로 5개 fold를 나누고, 각 fold마다 다른 네 fold에서만 bilingual 단어 사전을 학습한다.
- 정렬 오류를 피하기 위해 한·영 토큰 수가 같은 이름만 위치별로 사전 학습에 사용한다. 별도 음역·노이즈·메타데이터 모델은 없다.
- 검색 시 fit 선박을 카탈로그에서 제외한다. held-out 선박의 카탈로그 이름은 예측 후보로만 사용한다.
- 최빈 번역 조합과 가능한 모든 번역 조합을 비교한다. 표준화된 tokenization 외에 임계값 조정은 하지 않는다.

| 항목 | 결과 |
|---|---:|
| 평가한 실제 한글 행 | 1,191 |
| 모든 질의 토큰이 fit 사전에 존재 | 167 |
| 전체 토큰 커버리지 내 다중 번역 모호성 | 0 |
| 최빈 번역으로 정답 카탈로그 이름을 포함 | 163 |
| 다중 번역 lattice로 정답 카탈로그 이름을 포함 | 163 |
| 다중 번역으로 새로 포함한 정답 | **0** |
| 미관측 토큰 때문에 지원하지 못한 행 | 1,024 |

각 fold의 전체 학습 사전에서도 동일 한글 토큰이 서로 다른 영어 토큰으로 정렬된 경우가 0이었다. 즉 이 exact-token 방식이 문맥으로 해결할 모호성 자체가 관측되지 않았다. 결과·행별 증거·fold별 사전 모호성은 `LEXICAL_RESULTS.json`, `LEXICAL_ROWS.json`, `LEXICAL_AMBIGUITY.json`에 있다. 원본 train/catalog SHA256도 결과에 저장했다.

이 결과는 **이 exact-token 가설에 대한 부정**이다. 자모·음역·미관측 단어 전체를 포함한 모든 구조 모델의 상한은 아니다. 163/167은 선별된 지원 가능 행의 사전 커버리지이며, 전체 매칭 정확도나 C_vote 구출 수로 해석하면 안 된다.

## 연구 근거와 적용 한계

[Kirov et al., CL 2024](https://aclanthology.org/2024.cl-2.2/)는 문장 단위 음역에서 언어 문맥과 단일 언어 자료를 이용한다. 이 연구는 문맥의 가치를 뒷받침하지만, 현재 입력은 문장이나 주변 엔터티 없이 고립된 선박 이름이다. 논문의 수치를 선박 정확도 증가량으로 가져올 수 없다.

[Lin et al., NEWS 2016](https://aclanthology.org/W16-2701/)는 엔터티 연결 및 관련 언어 정보를 음역에 결합하는 방향을 제시한다. 현재의 카탈로그만으로 새 독립 관계 증거를 얻는 것과, 외부 지식베이스의 엔터티 문맥을 도입하는 것은 구분해야 한다. 외부 선박 DB나 행 간 관계를 도입하지 않았다.

권고: 이 어휘 방향의 ZIP이나 GPU 실행 묶음을 만들지 않는다. 추가 이득을 주장하려면 기존에 없는 실제 입력 신호와, 그 신호를 쓰는 새 모델의 선박 단위 held-out 증거가 먼저 필요하다.
