# C_vote 고이득 방향 검증 실행 묶음

이 묶음은 **C_vote 원본 가중치·원본 투표를 기준으로 한 오프라인 실험**입니다. 제출하거나 모델 ZIP을 만들지 않습니다. Arena가 고른 실험은 `EXPERIMENT.md`에 고정합니다. Opus의 원본·훈련·카탈로그·제출 파일을 수정하지 않습니다. ByT5는 실행하지 않습니다.

## 실행

1. `ASTRA_HIGHGAIN_L4.ipynb`를 Colab에서 열고 GPU를 선택합니다. 시간 검증에는 L4를 권장합니다.
2. 노트북의 업로드 셀에서 `ASTRA_HIGHGAIN_KIT.zip`을 선택합니다.
3. 기존 Drive의 `C_vote.zip` 경로를 확인합니다. 묶음은 원본 SHA256 `601c71ab3bc87ee5128305261c1708c432eb75dca53258e4d3841cce813a97d3`만 받습니다. 7GB 원본을 이 묶음에 중복 포함하지 않습니다.
4. 기본 `pilot` 104행으로 실행합니다. 전체 사전 고정 데이터는 `full` 400행입니다. 두 실행의 행이 겹치므로 두 결과를 합쳐 독립 표본으로 세지 않습니다.
5. 마지막 셀에서 `ASTRA_HIGHGAIN_RESULTS.zip`을 받아 Astra에게 전달합니다. 실패했더라도 오류·진행 로그가 담긴 결과 ZIP을 받습니다.

실행 시작·단계·하위 프로세스 제한 모두 2026-11-01 07:00 KST를 따릅니다. 마감 후 재시작은 거부합니다. 실험 단계는 최대 900초, 각 기준/재현 단계는 최대 1,800초이며 남은 마감 시간이 더 짧으면 그때 중단합니다.

## 검증이 의미하는 것

- 기준: 실제 C_vote 세 패키지를 원본의 동시 실행 구조로 돌립니다. 세 패키지 중 하나라도 실패하면 측정을 무효 처리합니다. 원본의 fallback 결과를 정상 기준으로 받아들이지 않습니다.
- 계측: v20 후보·기초 확률·상위20·신경망 점수, 112/HSW 후보, 실제 **110 gap**을 기록합니다. 원본 추론 파일을 덮어쓰지 않습니다.
- 재현: 결과를 보기 전에 정한 한글8+영문2행을 역순으로 원본 계측 없이 다시 실행합니다. 최종 답과 세 패키지의 답이 모두 일치해야 실험을 진행합니다.
- 비교: C_vote 대비 변경·구출·훼손, 깨끗한 이름 손해, 영문/보호 행 불변, 후보 누락/상위20 밖/재순위 실패/투표가 정답을 덮은 경우를 분리합니다.
- 시간: GPU 종류, 기준 실행과 실험의 실제 시간을 기록합니다. L4가 아니면 L4 시간으로 부르지 않습니다. 추가 GPU 모델 로딩·재현 검사는 진단 비용이므로 전체 실험 시간을 서버 추론 시간으로 부르지 않습니다.

## 데이터의 한계

104/400행은 공식 카탈로그에서 train·알려진 few-shot 선박·동명 선박을 제외하고, 오류를 보기 전 ID 해시로 고른 합성 스트레스 데이터입니다. 기존 Kanana/72B 한글 표기에 음절 삭제·중복·교환과 톤수 결측을 적용했습니다. 두 모델이 이미 사용하는 표기이므로 **SYNTHETIC / TABLE-SEEN / STYLE-BIASED**입니다. 일반화가 확인된 독립 검증이 아닙니다. 정답은 평가 단계에서만 읽습니다.

합성 이득만으로 제출 후보를 채택하지 않습니다. `COMPLETE`는 실행 완료이며 `submission_eligible`은 항상 false입니다. 실제 Public 오답 행·정답을 알 수 없으므로 Public 구출 수나 0.98 도달을 예측하지 않습니다. 실제 제출 대상의 3,000행 시간·600행 독립성 검사도 아직 수행한 것으로 표시하지 않습니다.

현재 0.9618922587(K507/E3506)에서 영문이 같다면 0.98 초과는 한글 순증14, 0.985 초과는 순증18이 필요합니다. 이 실험의 우선 목적은 그 규모의 오류를 다룰 후보 정보와 점수 신호가 남아 있는지 확인하는 것입니다.
