초안: 후보집합 확대가 먼저 떠오른다. 기존 500개 퍼지 후보에 112/HSW 후보를 넣고 신경망으로 64개까지 다시 점수화한다. 두 모델 합의면 v20 예측을 바꾼다. 높은 정확도로 잔여 한글 오답 다수를 고칠 수 있을 것이다. 간단한 예제로 동작을 확인한 뒤 GPU에서 실제 C_vote 비교한다.

문장별 비평:
1. K 확대 자체는 이미 112 KC50→200 무효, Opus 중복 위험. 주 문제는 조정된 base의 상위20과 0.25 convex cap이다.
2. 후보의 순위와 출처를 기록해야 absent/below20/score-cap을 구분한다. 64개라 해도 어떤 64개인지 고정해야 한다.
3. 모델 합의는 정확도나 독립성 보장이 아니다. native margin 고정과 불일치 abstention, train 제외, route 고정이 필수다.
4. 잔여 오류행도 모르는데 '다수'는 근거 없는 약속이다. en=hs 잠금이 있는 이상 가용 ceiling을 수치화해야 한다.
5. 예제는 실제 GPU 결과가 아니다. 반례가 반드시 있어야 하며 baseline trace 원형 보존, labels 분리, 실패 abort가 필요하다.
재작성 방향: 후보확대는 보조수단. 신경망 판단이 base/KoCat에 의해 차단되는 구조를 실험적으로 분리한다. 한 번의 고정 challenge로 주장할 수 있는 것은 정보획득과 reachable 오류범위이며 성능은 미측정으로 남긴다.
