ATTACK 1 [MAJOR] 구성요소 성공 플래그만 검사하여 누락·잘못된 voter ID를 정상 비교에 수용한다
Where: neural_rescue.py::validate의 `if p["components_ok"] is not True`, run_one의 catalog 검사는 p["ids"]에만 적용됨. 답변의 “구성요소 누락 … 모두 nonzero 종료/ABORT”.
Problem: en/hs의 비어 있지 않은 문자열 여부와 공식 catalog ID 여부를 실제로 검사하지 않는다. 제공된 fixture에서 p["en"]=None, components_ok=True를 두고 validate/run_one을 실행하면 예외 없이 baseline=C000, candidate=C064, reason=dual_view_rescue가 반환됐다. p["gap"]=4, p["en"]="NO_SUCH_CATALOG_VESSEL"이면 존재하지 않는 ID를 candidate로 반환한다. 실제 재현 명령은 제공된 test_neural_rescue.fixture/Scores와 neural_rescue.run_one을 그대로 이용했다. 부모가 반드시 올바르게 join한다는 계약은 적혀 있지만, 실행기가 누락·잘못된 voter를 자체 검증한다는 주장과 다르고 결합 실수를 실패로 막지 못한다. 과제의 “require component failure abort”를 완성하려면 en/hs/v20 모두 비어 있지 않은 공식 ID인지 검증해야 한다.

ATTACK 2 [MINOR] 확률 벡터의 합이0이어도 통과하고 진단기는 동일 입력에서0으로 나눈다
Where: neural_rescue.py::validate의 base/post 검사는 길이·유한성·음수 여부뿐. diagnose.py의 `mass=sum(...)` 다음 `(base[top[0]]-base[top[1]])/mass`.
Problem: fixture의 base를 전부0으로 바꿔도 validate가 통과하고 run_one은 C064를 정상 선택한다. 그러나 그 패킷을 diagnose.py로 평가하면 top20 mass=0이므로 ZeroDivisionError가 발생한다. 이는 사용자가 얻은 candidate 결과와 별도 정답 분석 사이에 허용 입력 계약이 다른 구체적인 경우다. 원본 정상 파이프라인에서는 나오지 않아야 하는 값이므로 추론 패킷 단계에서 합>0 및 필요한 확률 정합성을 검사하고, 진단 단계에서도 잘못된 패킷으로 명확히 중단해야 한다. 현재 테스트의 NaN 검사는 이 경우를 다루지 않는다.
