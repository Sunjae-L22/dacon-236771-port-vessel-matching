제안은 **기존 두 신경망의 후보 대조를 C_vote의 어려운 행에 다시 적용하는 실험**이다. v20을 네 번째 투표로 추가하지 않는다. v20 내부의 top20 제한·신경망 생략·75% 기본확률 혼합 때문에 배제된 후보를 기존 encoder와 Qwen이 함께 강하게 지지하는지 확인하고, 통과한 경우에만 v20의 한 표를 바꾼다. 판정은 HOLD이며 GPU 검증용 실행 함수까지 준비했다.

전제와 제한

1. 원본 C_vote ZIP과 세 구성 모델·카탈로그·입력의 SHA256을 고정한다. 원본 파일은 수정하지 않는다.
2. 영문, 110 gap≥4, HSW=112인 행은 변경하지 않는다. 기존 majority/all-different→v20 라우팅을 그대로 쓴다. 마지막 경우는 v20만 바꾸어도 최종 결과가 바뀔 수 없어서 계산을 생략한다.
3. 학습·few-shot 선박 제외를 유지하고, 행끼리 정보를 공유하거나 테스트 분포로 임계값을 맞추지 않는다. 라벨은 별도 평가기에만 들어간다.
4. 새 학습·ByT5·72B·KC/K/가중치 탐색·HSW 변경·외부 선박 DB·제출·모델 ZIP 제작은 없다. 로컬에서는 대형 체크포인트를 추출하지 않았다.
5. 작성물은 지정된 run 아래에만 저장했고 Python bytecode를 막았다. 실제 파일 읽기 분석은 기존 CPU.lock의 exclusive flock 안에서 단일 프로세스로 수행했다.

두 방향을 비교한 결과

| 방향 | 얻는 정보와 최대 범위 | 근거와 한계 | 선택 |
|---|---|---|---|
| 후보 생성의 별도 noisy-channel/복원 검색 | 풀 밖 정답을 새로 찾으므로 retrieval ceiling을 높임 | external/ksh/docs/fuzzy_retrieval_20261030.md의 v15→v18 Public 상승은 강한 선례. 그러나 이미 fuzzy500·KoCat50·음절 되돌림이 들어 있고, 옛 v17 오류의 74~92%는 풀 안에 있었다. 새 문자열 복원은 기존 fuzzy/Opus 방향과 겹치고 잘못된 복원이 늘 수 있음 | 보류 |
| frozen encoder→Qwen 후보 대조 | 풀 안 정답의 rank>20, confidence skip, 기본확률 혼합 억제를 함께 검사 | 실제 encoder_views.py는 top20만 평가하고 조건부 gap>1/3이면 신경망을 생략한다. 단순 신경망 비중 상승은 과거 encoder_confidence40에서 +8/−11, Δ−0.0007206으로 실패했다. 두 모델의 독립 지지와 대조 후보 간 여유를 요구하는 방식으로 한정 | 우선 실험 |

과거 음역/encoder 성과를 현재 C_vote 오답 25행의 증거로 바꾸지 않는다. 두 모델은 서로 다른 구조지만 오류가 독립이라는 보장도 없다. 이 실험의 목적은 더 큰 가중치를 찾는 것이 아니라 **이미 가진 신경망이 순위 병목을 실제로 풀 수 있는지** 확인하는 것이다.

실행할 고정 메커니즘

- 범위: 한글 AND gap110<4 AND HSW≠112. 원래 v20의 답을 incumbent로 둔다.
- 후보: 생산용 train exclusion과 KO_W 처리까지 마친 기본확률 top64, 기존 sim_llm/sim_key/sim_compact/sim_key_word 각각 top16의 합집합. incumbent를 먼저 포함하고 최대128개로 고정한다. 후보 수를 보고 설정을 바꾸지 않는다. 새 정답이나 다른 행의 후보는 넣지 않는다.
- 기존 `encoder:phonetic`으로 이 후보들을 scoring한다. 기존 `qwen:evidence`에는 encoder top8와 incumbent, 최대9개만 보낸다. 후보 ID 순으로 정렬하고 한 행 안에서 batch8씩 계산한다.
- 두 모델의 최상위 후보가 동일하고, 각각 자기 runner-up보다 raw logit이 1.0 이상 높으며 incumbent와 다를 때만 대체한다. logit 1.0은 사전 고정 실험값이지 확률이나 정확도 보장이 아니다. 불일치·작은 margin은 abstain이다.
- 마지막에는 원래 세 표의 라우터를 그대로 실행한다. 오류/누락/비유한 값은 abstain으로 숨기지 않고 실행 실패로 전파한다.

조건부 이득 상한은 명확하다. R을 원본 25개 한글 오류 중 위 범위에 있고, 정답이 후보128과 Qwen finalist에 도달하며, 두 view가 함께 지지하는 수라고 하면 **최대 순증≤R≤25**다. .98은 R에서 새 손실을 뺀 값이14 이상, .985는18 이상이어야 한다. HSW=112인 잔여 오류나 보호된 오류가 많으면 이 방식만으로 목표에 못 간다. 그 수는 원본 세 표와 독립 정답 없이는 알 수 없다. 후보 밖 오류는 이번 방식의 회복 상한이0이다.

완료한 로컬 검증

`astra/arena_highgain_20261101/run/scratch/a003/`에 다음 파일이 있다.

- `challenge.py`: 외부 로딩 가능한 순수 후보 선정/대조 함수와 `install_instance` 실제 통합 어댑터.
- `test_challenge.py`: 8개 테스트, 모두 통과(0.005초). base rank101 후보가 합법적 retrieval 신호로 들어와 기존 v20와 최종 vote를 바꾸는 positive activation, 두 view 불일치/작은 margin abstention, 영문/보호/고정 라우터 무호출, 라벨 제거, 후보순서·행순서·행부분집합 불변성, 학습선박 제외, 구성모델 실패/NaN abort, 원본 router 네 패턴을 검증했다.
- `evaluate_trace.py`: 정답을 추론 후에만 붙여 후보 부재/rank>20/confidence skip/neural misranking/route override와 rescue/harm을 분류한다.
- `probe_ceiling.py`, `proxy_ceiling.json`: 기존112 fold2/4 패킷4,670행을 읽은 별도 분석. gap<4인1,345행 중 오답246행; 정답 top20=203, rank21~64=7, 풀 밖=36이다. 따라서 이 오래된 proxy에서는 단순 후보 확대만으로 고칠 수 있는 추가 오류가7개에 불과하고, **상위 후보의 재판별이 더 큰 진단 대상**이다.

마지막 분석은 KC1·옛112 후보점수이며 C_vote/v20/HSW 출력이 없다. 203행을 실제 개선 가능 건수로 해석하면 안 된다. positive activation은 알려진 logits를 준 계약 테스트이며 실제 GPU 모델 정확도나 Public gain 측정이 아니다. 로컬에서 실제 frozen weights 대조는 아직 실행하지 않았다.

정확한 GPU 연결점과 I/O

원본 `model/ko/model/src/encoder_views.py::EncoderViewsEnsemble.load`의 해시 검사가 성공한 **이후 반환 인스턴스**에 다음을 호출한다. 해당 파일을 편집하거나 source_hashes를 다시 쓰지 않는다.

```python
from challenge import install_instance
model = install_instance(
    model, votes_by_id, excluded_vessel_ids,
    emit=write_trace_jsonl, enabled=True,
)
```

`votes_by_id[sample_id]`는 첫 원본 실행에서 확보한 `{v20:str, hsw:str, p112:str, gap110:float}`이다. 누락/실패한 voter의 fallback 출력을 정상 결과로 인정하지 않는다. `excluded_vessel_ids`는 원본 `train_vessels.json`의 고정 집합이다. 부모 tracer가 원본 세 출력을 모두 확보한 뒤 동일 입력을 replay할 때 붙인다.

어댑터는 `score_records(rows, signals, blocks)`를 감싼다. 원본 메서드의 결과를 먼저 얻고 실제 argmax가 첫 실행 v20와 일치하는지 확인한다. 이어 `model.baseline.score_groups(blocks)`를 호출하므로 원본 script.py가 나중에 설정한 `masked_score_groups`의 train exclusion·KoCat 처리도 유지된다. 기존 뷰 객체는 `model.views`의 `encoder:phonetic`, `qwen:evidence`를 재사용한다. 후보 레코드는 `model.r.catalog.iloc[sig["cand"]]`, ID는 `model.r.ids`에서 가져온다. extra scoring은 최대 encoder128+Qwen9 pair/적격행이다. CPU 기본확률 계산을 한 번 중복하는 비용이 있다.

`enabled=False`는 원본 score 배열을 그대로 반환한다. 활성화해도 abstention이면 원본 배열을 반환하고, 대체된 행에만 선택 위치가1인 벡터를 반환하여 원본 최종 argmax와 제외 루프를 통과시킨다. 모델 입력에는 이름·톤수·국제톤수·선종·국적의 허용 필드만 전달하며 sample_id/target/truth는 제거한다.

trace에는 sample_id, 원본 세 표·gap·최종값, 원본 풀 전체ID, base top20, 조건부 gap와 기존 neural skip 여부, 128후보·finalist ID, encoder/Qwen raw logits, 변경 이유, 후보 v20/최종값이 기록된다. 부모 tracer의 원본 확률·후보 생성 provenance와 합쳐 base rank가 왜 밀렸는지도 확인할 수 있다. out-of-scope 행의 풀 진단은 부모 원본 trace를 이용한다.

실제 paired 실행과 중단 조건

1. 원본 ZIP/공식 catalog/input/소스/weights hash, 환경 버전, L4/G4 장치명, 메모리, 시작시각을 기록한다. 원본115/C_vote의 세 구성 출력이 모두 완전한지 확인한다. source baseline 계약의 ZIP hash는 `601c71ab3bc87ee5128305261c1708c432eb75dca53258e4d3841cce813a97d3`이며 사용자 제출 ZIP과 동일하다는 추가 확인은 아직 없다.
2. no-change replay에서 모든 최종값과 세 표가 일치해야 한다. CPU-only proxy 결과로 대체하지 않는다. 각 행의 original v20 replay 불일치도 즉시 중단한다.
3. 사전 고정 해시순으로 적격32행에서 GPU 처리량·VRAM을 측정한다. 전 행 적용 추정 총시간이1,800초를 넘거나 OOM/불완전 voter/NaN/후보ID 불일치가 생기면 전체 후보 평가를 중단한다. threshold를 바꾸거나 처리된 행만으로 후보를 만들지 않는다. 전역 watchdog1,800초, 종료 여유60초를 둔다. 실제 시간은 아직 미측정이다.
4. 전체 후보 실행 후 고정16행, 역순, 단독행으로 replay한다. 최종 ID는 정확히 일치해야 한다. pair logits 오차도 저장하되 최종 예측 불일치를 허용하지 않는다. 원본 출력·후보 출력은 평가용 JSONL/CSV이며 제출용 model ZIP을 생성하지 않는다.
5. 라벨 없는 실제 test는 변경행 수, 후보 이동, router 영향, 비용·재현성만 증명한다. 정답이 없다면 rescue/harm을 추정하지 않는다.
6. 보조 stress는 공식 catalog와 기존 허용 한글표의 교집합에서 모든 알려진 train/few-shot 선박을 제외하고, vessel_id SHA256순 첫256척을 고정한다. 같은256척에 clean/중앙 음절삭제/중앙 인접교환/톤수결측을 각각 만들어 비교한다. 항상 `SYNTHETIC, TABLE-SEEN/STYLE-BIASED`라 표시하고 원래 exclusion을 유지한다. 이 결과만으로 배포 자격을 주지 않는다.
7. 배포 판단에는 모델·few-shot·고정표의 생성 스타일과 독립된, 학습선박과 겹치지 않는 실제 주최측 held-out query와 정답이 필요하다. 없으면 사람이 모델 예측을 보지 않고 작성·검수한 별도 질의와 확정 선박ID를 독립 파일로 봉인해 추가 진단할 수 있으나 이것도 Public 분포의 대용일 뿐이다. 현재는 HOLD다.

복귀 산출물은 `baseline_trace`, `challenge_trace`, `paired_predictions`, `hash_manifest`, `timing_hardware`, `invariance_report`와 별도 라벨 평가표다. 평가표에서 pool absence가 우세하면 retrieval 방향으로, rank>20가 우세하면 admission으로, top20 포함·두 view 오판이 우세하면 현 frozen scorer의 한계로 판단한다. 합성 순증만 높거나 변경0인 경우도 실패/무효 근거를 남기며 자동 제출하지 않는다.
