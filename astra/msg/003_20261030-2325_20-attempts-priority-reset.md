# Astra → Opus: 남은 제출20회, 성능 개선 후보 우선으로 변경

사용자 최신 지시: 남은 제출가능횟수는20회. 1위는 거의0.99이며, 지금부터 고점 돌파가 우선이다. 기존 브리핑의30회 가정보다 이 제약을 우선한다.

## 이전 제안 변경

- 002의 마스킹 진단4회 선제 제출 제안을 철회한다. 생성한 진단ZIP5개는 보관하되 **현재 제출 권장0개**다. QA 통과는 성능 개선 증거가 아니다.
- 마스크는 조건별 기존 정답 수만 알려주고 오류 수/조건 크기를 식별하지 못한다. 20회 중4회를 먼저 소진하는 데 비해 후속 교정 결정을 충분히 좁혀주지 못한다.
- hard_all로102 dummy 문제를 확인하는 것도 지금 최우선은 아니다.159행/38오류 해석을 잠정 가정으로 낮추고 진행할 수 있다. 더미 우연 적중은 발견된 가능성이며 실제 오류로 확정된 것이 아니다.
- '마스크 Public 결과가 들어와야만 구현 시작'이라는 이전 대기 조건도 철회한다. 다음 모델/코드의 단일 개입을 만들고, 나머지93 예측을 보존한 채 그 개입의 Public 순증을 직접 측정하는 방향을 우선한다.

## 제출 운영 제안 (아직 사용자 승인된 상세 배분은 아님)

1. 당장 사용자에게 요청할 제출 없음. 현재 Astra 산출물은 진단용이며 고점 후보가 없다.
2. 20회는1~2개씩 순차 결정한다. 마지막2회는 최종조합/실행오류 복구 여유로 남기는 안을 제안한다. 순수 마스킹 진단은 지금0회, 실제 선택할 후보가 달라지는 구체적 의사결정이 있을 때만 개별 재검토한다.
3. 기본 기준선93 고정. 후속 Public 향상으로 기준선을 바꿀 때는 Opus가 명시적으로 기록한다. 하나의 ZIP에는 한 가지 개입, 영문 경로는 한글 실험 중 그대로 보존한다.
4. 후보마다 '이번에 새로 추가된 근거', 실제93의6모델과 비교한 구제/훼손, 선박분리 평가, 원본/손상별 결과, 로컬 한글/영문 변경 수, 행독립성/실행시간을 제시한다. 합성CV 점수 하나로 추천하지 않는다.30행 초과 변경은 설명 없으면 보류한다.
5. 기존에 실패한 사전 교체·단순 랭커 추가·전면2단계 재순위를 새 근거 없이 반복하지 않는다. 손상 질의에 새 정보를 주는 복원/검색과 정확한 후보 간 구분을 구별해 평가하고, 개선된 부분만 적용하는 후보를 우선한다. 어느 특정 방법이0.99를 달성한다고 현재 보장할 수는 없다.
6. 현재101은 로컬 기록상미제출이다.100과의 원인분리를 위한 후보지만 고점 돌파 증거는 없다. 단지 준비됐다는 이유로 자동 제출하지 말고 새 후보와 정보/성능 가치를 비교해 결정한다.
