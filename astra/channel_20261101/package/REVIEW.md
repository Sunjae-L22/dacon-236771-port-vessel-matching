# C_vote CPU 오류 채널 — 실제 비교 실행 전 검토

2026-11-01 03시대. 상태: **Colab 진단 실행용, 제출 후보 아님.** Public 제출 0회, 새 신경망 학습 0회. 작업 파일은 astra 아래에만 작성했다. Opus의 72B 생성·KoCat 랭커·F1/융합 파일은 수정하지 않았다. 07:00 이후 새 실험을 시작하지 않고 실행 중에도 중단한다.

## 무엇이 달라졌나

이전 frozen encoder/Qwen 후보 확대는 권하지 않는다. 이번 방법은 기존 한글 표기와 관측 이름 사이에서 **음절 삭제·중복·인접 교환으로 도달하는 모든 0~2회 경로의 확률을 합산**하는 CPU 모듈이다. 후보를 v20 상위20개/97개로 제한하지 않고 전체 허용 카탈로그의 이름을 검색한다. 여러 한글 alias는 선박별 균등 prior로 평균하며, 표기가 많은 선박에 무조건 가산하지 않는다.

HSW의 EM/graphone 및 기존 Astra 사전 복원에도 비슷한 구성 요소가 있다. 새 주장 범위는 전체 이름의 명시적인 관측 오류 확률, 겹치는 연산 경로의 합산, 정규화된 alias 증거다. 기존 112·v20와 같은 표기 정보를 재사용하므로 독립된 새 지식이나 독립 전문가라고 부르지 않는다.

파라미터는 실제 영문 train의 카탈로그→관측 이름으로 학습했다. 정답 확률의 보정값이 아니며, 영문 문자 오류 비중이 한글 음절에도 같다는 것은 미검증 가정이다. 검색 범위 밖의 표기·3회 이상 오류·다른 종류의 오류는 설명하지 못한다.

V3 적용 조건은 한글, **원본110 gap<4**, 모델 내 질량 비중≥0.99, winning vessel의 어느 alias로도 identity/삭제1회/삭제2회만으로는 질의를 설명할 수 없는 경우다. 마지막 조건은 개발 세트의 clean 피해를 보고 추가했으므로 개발 결과를 검증 성과로 세지 않았다. 삭제+교환은 허용하며, 실제 원인이 교환/중복이라는 보장은 없다. 112=HSW 행도 적용 범위에 포함한다.

## 검증 순서와 결과

1. 초기 V2를 실제 원본112/HSW 가중치로 개발64척·400행에 적용: 112 대비 **45구출/3훼손**. 훼손이 모두 clean이라 **기각**했다. 예: 정상 '가스비너스'를 더 긴 다른 선박명에서 삭제된 이름으로 오해했다.
2. V3의 삭제-only 보류 조건을 개발 결과에서 정하고 `V3_PREREG.json`에 코드·파라미터 해시와 검증64척을 고정했다. 개발 결과39/0은 개발치일 뿐이다.
3. 다음64척을 한 번 검증한 결과는 아래와 같다. 이후 임계값이나 규칙을 재조정하지 않았다.

| 검증 조건 | 행 수 | 원본112 정답 | V3 정답 | 구출 / 훼손 |
|---|---:|---:|---:|---:|
| clean + 톤수 | 64 | 64 | 64 | 0 / 0 |
| clean + 톤수 결측 | 64 | 58 | 58 | 0 / 0 |
| 삭제 | 64 | 46 | 46 | 0 / 0 |

한글40행 변경, 영문0행 변경. 구출36행은32척이다. 이득27/36이 복합 오류에 집중되므로 균형 합성 세트의 평균을 실제 test에 외삽할 수 없다.

이 중 **10행(9척)은 112와 HSW가 같은 오답을 반환**했다. C_vote 규칙상 이 행들의 기존 최종 답도 같으므로, 해당 합성 세트에서 C_vote 대비 구출이 논리적으로 확인된다. 전체400행 중289행은 CPU 두 모델과110 gap만으로 C_vote 답을 확정할 수 있고111행은 v20가 필요하다. 미확정 행의 적용 대상51개 중 새 답47개는 정답,4개는 오답이다. 따라서 동일한 CPU 출력이라는 조건에서 이 합성 세트의 순증 범위는 +6~+57행이다. **이는 Public 예상 범위가 아니다.** 원본 ZIP 전체 실행과 비교할 때 CPU 파일 해시도 다시 확인한다.

## 평가 자료의 한계

- 공식 train의 실제 한영 선박명에서 같은 위치 단어 대응을 추출하고, 최소2척 지지·75% 일치인70단어만 사용했다.
- 전체 train 정답5851척 및 알려진72B/Kanana few-shot 이름을 제외한 catalog 선박에서, 고정 SHA256 순서로 개발64척과 검증64척을 정했다.
- 질의는 KoCat/Kanana 한글 표기에서 복사하지 않았다. 하지만 train 단어로 **조합한 합성 전체 이름**이며 사람의 독립 실제 질의가 아니다. 원본 모델도 같은 train 단어 정보를 접했다.
- 0.99는 제한된 alias/오류 모델 안의 상대 질량이다. 정답 확률99%가 아니다. V3 조건도 모든 잘못된 표기를 해결하지 않는다.
- 실제 영문 별도 holdout1097형에서는 기본 이름 검색과 채널 모두1095정답으로 **이득0**이었다.
- 실제 한글 이름에 노이즈를 주입한54척 이름검색 비교의20/0은 원본112/C_vote와 다른 실험이다. 본 표와 합산하지 않는다.
- C_vote Public K507/E3506에서 영문을 유지해 .98을 넘으려면 한글+14, .985에는+18이 필요하다. 지금 결과만으로 이를 예측할 수 없다.

## QA와 시간

- 정규화 확률 질량, 겹치는 교환/반복/상쇄 경로 검사 통과. 논리 검사에서444개 허용 support 중 nondeletion 조건 반례0.
- 명시적 선박 제외, exact 파라미터 키·유한값 검사, gap 출처 확인. 최종 결정은 각 행의 지역 변수만 사용한다.
- CPU 통합 fixture에서 순서·중복600회 불일치0, 영문 변경0, 보호행 변경0. **v20 대역 fixture이므로 전체 C_vote600행 검사가 아니다.**
- MacM4 개발400행 CPU 질의8.36초, 초기화/600회 재검사 포함22.68초. 검증400행 원본112와HSW 및 CPU 시간은 개별 JSON에 기록했다. **L4 시간은 미측정.**
- 공식 local_check의3000행 시간 및 전체600행 일관성은 미실행. 합성 검증만으로 제출 후보를 만들지 않는다.

## Colab 실행 묶음

`ASTRA_CHANNEL_DIAGNOSTIC.ipynb`를 F1 완료 세션에서 열고, `ASTRA_CHANNEL_DIAGNOSTIC.zip`만 업로드한다. 원본 C_vote ZIP은 기본 Drive 경로에 있어야 한다. 경로가 다르면 노트북의 CVOTE만 바꾼다.

원본3모델을 동시에 한 번 실행하여 최종 답·개별 답·110 gap을 저장한다. 점수 모델과 원본 child 실행문은 수정하지 않는다. 실패한 투표자를 빠뜨린 fallback 결과는 비교 자료로 받지 않고 실패 처리한다. CPU 채널은 저장된 예측으로 비교하며, clean 피해·112/HSW 공동 오답·세 모델 공동 오답 구출을 구분한다. GPU 모델 추가 학습이나 새 가중치 다운로드는 없다.

전체 실행30분 또는07:00KST 중 먼저 오는 한도에서 중단하며 가능한 결과를 `ASTRA_CHANNEL_RESULTS.zip`으로 묶는다. 400행 시간은 제출용3000행 시간으로 환산하지 않는다. 다음 단계는 이 결과를 읽어 실제 C_vote 대비 훼손과 실행 시간을 확인하는 것이다.
