# 112 기준 ByT5 후보의 시간·정확성 판정

활성 기준은112(Public501/3506)이다. 기준ZIP SHA256은 `BASELINE_CONTRACT.json`에 고정했다. 사용자 보고 서버 L4 실행시간은710초(11분50초), 전체 제한은1800초다. 산술상 차이1090초(18분10초)는 추가 모듈의 보장된 허용시간이 아니다.

## 정확성 비교

- 모델·표·특징 변경을 새로 개발하지 않고, 실제 배포에서는 원본112의6개kc랭커와KoCat50을 기준으로 쓴다. 현재 fold KC1개 대조는 탐색용이며 실제112 앙상블의 held-out 성능으로 부르지 않는다.
- 검증 표의 비교 기준은112 예측으로 고정한다. 정답은 검증 데이터의 원래 선박ID다. 110 대비 이득은 중복 설명에만 쓴다.
- 구출:112오답→신규정답. 훼손:112정답→신규오답. 특히110오답→112정답→신규오답을 별도 집계한다. Public 순증+8의 실제 행ID는 알 수 없으므로 검증셋에서만 이 중복을 측정한다.
- 기본 적용 범위는원래110 gap<4이면서112 평균gap<4인 한글이다. 112가 새로 확신하는 행은 보존한다. 실제 정답 여부로 추론범위를 정하지 않는다.
- 깨끗한 원본 이름 훼손0,영문 변경0,범위 밖 변경0을 각각 확인한다. KoCat few-shot 대상은 주검증에서 제외하고,동일한 행집합으로 모든 방법을 비교한다.

## 실행시간

- G4 생성/채점 시간을710초에 더해 L4 시간이라고 보고하지 않는다.
- 실제 후보가 검증을 통과한 뒤 L4에서 원본112와 후보를 동일 입력·환경으로 실행한다. GPU명,torch/transformers 버전,CPU스레드수,입력행수,한글수,ByT5가동행수,후보 수를 남긴다.
- 시간은 프로세스 시작부터 출력 저장까지 측정한다. 모델 로딩,카탈로그 구성,112추론,생성검색,확장후보 피처/재순위,신경망 채점,프로세스 간 파일 전달을 모두 포함한다.
- 원본 local_check의3000행과600행 부분집합/순서 검사를 실행한다. 112와 신규 ZIP의 변경행 및112추적값 일치를 검증한다. 기존 작은 시험모델의312.1초 결과를 새 후보의 QA로 재사용하지 않는다.
- 3000행은 숨겨진 전체 test와 동일하다고 가정하지 않는다. 동일 L4 입력의112/신규 실측,사용자 보고710초,서버 전체시간 추정과 그 한계를 분리한다. 충분한 시간 여유를 확인하지 못하면 제출 후보로 올리지 않는다.
- 전체 제한30분 초과는 기각. 가급적 전체25분 이내의 여유를 확보한다. 실제 서버 전체시간은 제출 전 직접 확인할 수 없는 경우가 있으므로 이를 실측이라고 쓰지 않는다.
