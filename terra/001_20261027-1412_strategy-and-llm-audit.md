- [기록 확인] 33번 0.9397, 36번 0.9403, 42번 0.9336. 같은 방식 6개→12개 모델의 이득은 반올림된 점수 기준 0.0006입니다.

### 우선 검토할 새 방향

**A. 후보 조건부 문자/바이트 점수: 가장 먼저 준비할 신경망 경로**

관측 이름 `엠에스 프리지아`를 보고 영문을 자유 생성하는 데서 멈추지 말고, 후보 `MS Freesia`와 `Serene Monaco` 중 어느 쪽이 그 한글 관측을 잘 설명하는지 점수를 냅니다. 예를 들어 영문→한글 모델의 `log P(관측 한글 | 후보 영문)`를 기존 랭커의 새 피처로 쓰는 방식입니다. 이 방향은 한글에서 영문으로 가는 고유명사의 여러 가능한 철자 문제를 후보 집합으로 제한합니다.

- 1차 파일럿은 기존 상위 10~20개 후보에만 적용합니다. 후보 누락은 별도로 측정합니다.
- 학습은 실제 train 한영 쌍을 기준으로 하고 v1 생성 쌍은 보조로 사용합니다. 생성 표기와 실제 표기의 가중을 구분합니다.
- 기본 모델 예시는 ByT5-small입니다. 바이트 단위 모델의 철자·발음·잡음 처리 가능성은 원 논문에 근거하지만, 이 대회에서의 우위나 L4 30분 충족은 아직 검증하지 않았습니다.
- 미세조정 없이 바로 역음차가 된다고 가정하면 안 됩니다. 공식 모델 카드도 후속 과제 미세조정을 요구합니다.
- 추론 단계에 카탈로그 전체의 한글명을 LLM으로 새로 생성하는 방안은 우선 제외합니다. 운영진의 증강 답변은 train 이용에 한해 허용한다고 되어 있습니다. 카탈로그는 공식 후보 검색에 그대로 사용합니다.

근거: [ByT5 논문](https://arxiv.org/abs/2105.13626), [Google 모델 카드](https://huggingface.co/google/byt5-small), [DACON LLM 증강 답변](https://dacon.io/competitions/official/236771/talkboard/418501). 논문이 이 대회의 성능을 보장하는 것은 아닙니다.

**B. 이름 전문가와 메타 전문가의 조건부 결합: 비용이 낮은 구조 변경 후보**

15% 개명 증강은 이름을 믿어야 하는 행과 무시해야 하는 행을 한 랭커에 함께 학습시킵니다. 한글 이름 근거가 충분한 행에서는 이름 중심 점수를 유지하고, 이름 근거가 약할 때만 톤수·선종·국적 점수를 강하게 사용하는 두 전문가 결합을 검토할 수 있습니다. 단순한 고정 이름 임계값이나 단조 제약을 다시 넣자는 뜻은 아닙니다. 전환 기준은 선박 단위 OOF에서 학습하고 고정해야 합니다.

**C. 문자 dual encoder: 후보 누락이 남을 때의 두 번째 신경망 경로**

한글과 영문 이름을 공통 공간으로 보내 카탈로그 임베딩을 미리 계산할 수 있습니다. 기존 후보에 합치는 보완 채널로 시작하고, GT가 비슷하거나 철자가 비슷한 후보를 어려운 음성 예제로 사용합니다. 동일 이름을 가진 다른 선박을 이름 모델에서 무조건 음성으로 주면 모순이 되므로, 동일한 정규화 이름은 복수 양성으로 처리하고 선박 구분은 메타 피처에 맡겨야 합니다.

**D. 일반 cross-encoder와 대형 LLM 직접 판단은 후순위**

현재 실제 한글 선박은 382척입니다. 넓은 의미 유사도보다 음차·약어·짧은 이름의 문자 대응이 핵심일 가능성이 있어, 일반 임베딩이나 범용 LLM의 크기 자체를 성능 근거로 보지 않겠습니다. 문자/바이트 점수가 보완 신호를 만드는지 확인한 뒤 확장합니다.

### 원인 우선순위

1. **합성 행의 양과 선박별 노출량 증가** [구성 변화 확인, 성능 원인은 가설]. 가중 없이 모든 LLM 행을 추가하므로 기존 실제/증강 행 대비 합성 표기의 영향이 커집니다.
2. **추가 표기의 평균 품질 또는 실제 표기와의 거리** [대리지표 및 개별 잘못된 접두 표기 확인]. 프롬프트 예시 선박을 제외하고 v1/v2가 모두 남는 230척에서, 실제 train 한글명과의 평균 문자열 유사도는 v1 0.741, v2 0.689입니다. 반면 선박별 가장 가까운 표기는 v1 0.787, v2 0.795입니다. 일부 유용한 다양성과 많은 낮은 유사도 표기가 함께 추가된 모습입니다. 실제 이름도 손상됐을 수 있고 다른 유효 음역도 있으므로 이 수치를 정답/오답 판정으로 쓰면 안 됩니다.
3. **사전 변화 및 학습 피처 자기참조** [구조 확인, 손해 크기 미측정]. 기존 키 120개가 바뀌었고 키 16,351개가 새로 생겼습니다. 실제 쌍만으로 만든 사전의 키 중 v1→v12에서 대응이 달라지는 것은 4개였습니다. 같은 생성 쌍을 사전에 넣고 그 행의 랭커 피처도 만드는 구조는 새로운 선박 추론보다 쉬운 학습 피처를 만들 수 있습니다.
4. **temperature 0.9 자체가 주원인이라는 설명** [미확정]. v2는 프롬프트·예시·생성 수·노출량을 함께 바꿨고, v1에도 샘플링 표기가 있습니다. 온도만 원인으로 특정할 수 없습니다.

사전의 영문 대응 변경은 여러 타당한 철자 사이의 선택일 수도 있어 곧바로 오염이라고 부르지 않겠습니다. 첫 독립 fold의 원본 167행에서는 v1/v12 사전 모두 GT 창 내 이름 순위 @1=1.000이었습니다. 원본 입력에서 이미 포화돼 있다는 뜻이며, 42번 하락을 설명하는 증거는 아닙니다. 추가 손상/다른 fold의 결과는 `experiments/20261027_llm_audit/REPORT.md`에 정리합니다.

### 제출 2회로 사전과 랭커를 분리하는 2×2

| 실험 | 사전 | 랭커 학습 LLM 행 | 상태 |
|---|---|---|---|

| B | v1 | v1+v2 | 신규 대조 |
| C | v1+v2 | v1 | 신규 대조 |

한 원인당 제출 한 번 이하라는 조건이라면 **로컬에서 후보를 걸러 B/C 각 한 번**이 현실적입니다. 네 원인을 네 번의 제출로 따로 찾아야 한다고 보지는 않습니다. 오늘 두 슬롯이 남았다는 정보는 전달문 기준이며 실제 잔여량은 사용자가 확인합니다.

후속으로는 v1의 선박별 표기 수 `n_v`를 그대로 유지하면서 v1+v2 중 `n_v`개만 뽑는 실험 E를 권합니다. 총 7,967행·4,710척을 유지하므로 수량·선박 노출량을 고정한 채 표기 변경을 비교할 수 있습니다. 그 다음 greedy와 sampled를 선박/행 수가 같은 조건으로 비교합니다. 무조건 높은 KoMatcher 표기만 고르면 기존 규칙의 선택 편향이 다시 생깁니다.

### ±0.004의 해석 수정

18번 0.9298과 27번 0.9259의 차이는 증강 난수에 따른 **재학습 변동의 한 관측값**입니다. 동일 제출물의 채점 잡음, 표준편차, 95% 신뢰구간, 모든 변경에 적용할 ±0.004 한계가 아닙니다. 같은 시드 묶음을 짝지어 비교하고 로컬에서는 선박 단위 paired bootstrap을 사용하겠습니다. 기존 두 점수만으로 0.003 개선을 무조건 기각하거나 0.005 개선을 확정하지 않겠습니다.

## 질문 4. 더 나은 로컬 검증

### 검증 대상을 세 층으로 분리

1. **실제 한글 표기의 선박 분리 검증:** 382척이 실질적인 독립 표본 규모입니다. 같은 선박의 반복 행과 그 변형을 독립 표본으로 세지 않습니다. 실제 원본 표기의 성능 보존을 먼저 봅니다.
2. **기존 변형별 강건성 표:** 오타, 자모, 어순, 절단, 단어 삭제를 각각 보고, 전체를 동일 비율로 평균낸 단일 점수를 Public의 대리 점수로 삼지 않습니다. 여러 변형을 같은 배에 만들면 불확실성은 배 단위로 계산합니다.
3. **새로운 생성 방식의 독립 점검:** 증강 생성기와 같은 방식으로만 검증 사례를 만들지 않습니다. 실제 train 표기와 OOF 실패 유형을 우선 사용하고, 생성 검증은 별도 보조 지표로 둡니다.

### 반드시 분리해서 기록할 값

- 언어별 후보 Recall@K.
- 정답이 후보에 있을 때의 랭커 정확도.
- 이름이 비슷하고 톤수가 같은 자매선, 이름/톤수가 충돌하는 행, 숫자가 있는 이름, GT 창 밖 정답을 각각 분리.
- 실제 원본 성능, 변형별 행 정확도, 선박별 평균 정확도, 후보간 점수 차이와 보완 오류 수.
- 원본 점수를 올리며 강건성을 크게 깎는 변경, 또는 특정 변형만 고치는 변경을 명시.

### LLM 검증의 정보 격리

기존 fold0 검증 선박 중 생성 예시에 v1은 7척, v2는 20척이 포함됐습니다. 생성된 검증 선박 행만 지우는 것으로 완전한 독립성이 보장되지는 않습니다. 전역 train으로 만든 선별 점수도 fold 밖 정보를 포함할 수 있습니다.

이번 사전 진단에서는 v1/v2 프롬프트 예시의 합집합 108척을 모두 학습 쪽에 두고, 나머지 선박에 기존 seed42 분할을 적용했습니다. 생성 표기의 0.70 선별 점수는 학습 부분의 실제 쌍만으로 다시 계산했습니다. 최종적으로 모든 선박을 공정하게 평가하려면 fold별 예시 선정과 생성을 다시 해야 합니다. 지금 검증은 프롬프트 예시 선박을 평가하지 않으므로 그만큼 평가 범위가 줄어듭니다.

### 전달문에서 완화해야 할 결론

- 진단 10은 높은 이름 점수와 정답이 함께 관측된 비율이지, 전체 깨끗한 이름 비율을 확정하지 않습니다.
- 진단 14의 0은 결측 조건에서 맞힌 Public 행이 관측되지 않았다는 결과입니다. 전체 test 한글 톤수 결측 0을 증명하지 않습니다.
- 진단 13의 0과 train 선박 사후 제외의 이득은 Public에서 유용한 경험적 근거입니다. 호출부호 변경·결측이나 Private까지 선박 비중복을 증명하지는 않습니다.
- 개명 증강의 이득은 그 증강이 일반화를 도왔다는 근거입니다. 숨은 test에 실제 개명이 일정 비율 존재한다는 유일한 설명은 아닙니다.
- 공식 규칙은 test의 다른 행이나 분포 사용을 금지합니다. 숨은 행을 출력·기록하거나 추출하는 진단을 추가하지 않겠습니다. 앞으로 슬롯은 정상 예측 후보의 대조에 사용합니다.
