## 2. 추가로 발견한 출처 판별 오류: 고정 1,191행

현재 v4 `_fit_train_pairs`에는 메타데이터가 없고 행이 1,250개를 넘으면 앞의 1,191개를 실제 train, 나머지를 LLM으로 보는 경로가 있습니다.

```python
if not has_meta and len(all_recs) > 1250:
    real_records.extend(all_recs[:1191])
    llm_records.extend(all_recs[1191:])
```

현재 전체 제출 stats가 **실제 한글 1,191행 다음에 LLM 행을 저장한 순서**를 유지할 때는 맞을 수 있습니다. 하지만 fold에서는 실제 한글 행 수가 달라집니다. 출처를 지운 채 저장하거나 순서를 바꾸면 위생 필터가 잘못 적용될 수 있습니다.

아주 작은 카탈로그로 분류 경로만 점검했습니다. 선박 매칭 성능을 측정한 실험은 아닙니다.

| 입력 | 실제로 넣은 real / LLM | v4가 판별한 real / LLM |
|---|---:|---:|
| 이름·ID 두 열만 합친 1,252행 | 950 / 302 | **1,191 / 61** |
| `KoMatcher(cat, real, llm_pairs=llm)` | 950 / 302 | **950 / 302** |
| TRAIN_/LLM_ sample_id 보존 | 950 / 302 | **950 / 302** |

첫 경로에서는 LLM 241행이 실제 데이터로 취급됩니다. **이 사실만으로 Argon의 기존 OOF가 반드시 이 경로를 썼거나 누출됐다고 단정하지 않습니다.** 평가 harness와 stats 형식을 확인해야 합니다. 다만 새 v4-lite와 OOF에는 이 암묵적 가정을 가져가지 않는 편이 좋겠습니다.

권장 방식은 이미 지원되는 명시적 인자입니다.

```python
km = KoMatcher(catalog, real_pairs, llm_pairs=llm_pairs)
```

제출 통계도 `ko_pairs_real`, `ko_pairs_llm`을 나누거나 sample_id/source를 보존하면 됩니다. 기존 `stats['ko_pairs']` 호환 경로가 필요하면 기존 패키지의 선언된 레코드 수를 manifest로 읽고 검증해야 하며, fold에서도 항상 1,191개라고 추측하지 않아야 합니다.

## 3. 실험 해석에서 두 가지만 더 구분

### v4-lite는 두 변경의 조합

ch 수정과 LLM 위생을 함께 넣은 v4-lite를 33번과 비교하면 **두 변경의 합친 효과**를 확인합니다. "한 번에 한 변경" 원칙에 엄밀히 맞는 단일 변경 실험은 아닙니다. CPU가 병목이라 두 변경을 묶어 먼저 시험하는 선택은 가능하되, 결과 이름을 조합 실험으로 기록하고 로컬에서는 ch-only/hygiene-only도 구분하는 것이 좋겠습니다. 당장 네 종류의 전체 6모델 빌드를 모두 요구하는 것은 아닙니다.

### 패치 ZIP의 점수는 재학습 실험과 별도

36 패치는 matcher 변화가 기존 랭커 피처를 바꾸는 진단입니다. 42 패치는 여기에 KO_DICT 0→1도 섞입니다. 따라서 42 패치와 42의 차이를 v4만의 효과로 부르면 안 됩니다. 재학습 없이 후보/피처를 바꾸는 점검에서 하락하더라도, 해당 수정으로 일관되게 재학습한 모델까지 기각할 수는 없습니다.

기존 진단에서 "test 절반이 손상", "test 전부 train 미등장"은 아직 추정 수준이라는 경계도 유지하겠습니다. 슬롯이 많아져도 숨은 test 행·정답을 기록하거나 복원하는 진단은 추가하지 않고 정상 예측 후보의 대조에 사용합니다.

## 4. ByT5 파일럿 준비 범위

먼저 제한된 독립 선박 파일럿으로 유용성과 시간만 확인하고, 통과한 뒤 전체 OOF로 확장합니다.

- 신경망 입력은 공식 train에서 얻은 영문명, 출력은 실제 한글명입니다. v1 생성 쌍은 출처와 가중을 구분한 보조 자료입니다.
- train/catalog 외의 선박 정답은 사용하지 않습니다. 카탈로그 미등장 단어를 LLM으로 추가 생성하는 방안은 보류합니다.
- 기존 후보 영문명에 대한 관측 한글의 teacher-forced 조건부 점수부터 측정합니다. 자유 생성과 beam search는 초기 파일럿에서 제외합니다.
- 전체 학습 33/36 모델을 train 행에 적용한 점수를 OOF 기준선으로 사용하지 않습니다. 기준 랭커도 해당 평가 선박을 보지 않은 상태여야 합니다.
- 신경망이 본 행의 점수로 결합기를 학습하고 미지 선박에 적용하는 자기참조도 피해야 합니다. 처음에는 선박 단위 신경망/기준 모델 학습, 결합 기준 조정, 최종 평가를 별도 분할로 두는 방식이 가장 명료합니다.
- 이 첫 단계는 5-fold 전체 OOF가 아니라 **독립 holdout 파일럿**으로 부릅니다. 전체 OOF와의 차이를 결과에 명시합니다.
- L4 처리량은 실제 이름 길이별 쌍으로 측정하고 모델 로드·후보 검색·신경망 점수화·저장 시간을 합쳐 예산을 계산합니다.

구체적인 준비 기준은 `terra/byt5_pilot/PLAN.md`에 저장했습니다. 이번 확인에서는 GPU 실행이나 추가 CPU 모델 학습을 시작하지 않았습니다.
