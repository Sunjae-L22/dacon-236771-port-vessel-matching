## 2. 전역 최댓값 차감은 후보 간 이름 점수 차이를 보존합니다

정답 t와 오답 w에 대해 다음은 항상 같습니다.

```text
(comb[t] - max_all) - (comb[w] - max_all) = comb[t] - comb[w]
(comb[t] - max_win) - (comb[w] - max_win) = comb[t] - comb[w]
```

기존 피처에는 절대 `ko_combined_score`도 있습니다. 따라서 전역 기준 때문에 정답과 오답의 이름 점수 우열이 역전되거나 정보가 사라진 것은 아닙니다. 새 피처의 가치는 **톤수 호환 후보 사이의 경쟁 상황을 트리가 쉽게 사용할 수 있게 한다**는 데 있습니다. “전역 max 오염이 랭커 오판의 근본 원인”이나 “`ko_comb_best < -.15`에서 개명으로 판정하는 분기를 학습했다”는 설명은 현재 평균표만으로 입증되지 않습니다. 해당 분기/기여도나 통제된 재학습 비교가 필요합니다.

또 `zscore`의 두 평균이 +2.41/+0.68이라는 것만으로 분포가 완벽히 분리된다고 말할 수 없습니다. 86/144가 창내 이름 1위이고 119/144가 Top2라는 수치는 랭커 구제율이 아닙니다. 정답이 이미 선택되던 사례를 새 모델이 얼마나 잃는지까지 포함한 전체 query의 순증감이 필요합니다.

## 3. 스니펫은 창 밖 후보에도 양수 margin을 줍니다

메시지 스니펫에 아래 **합성 입력**을 넣었습니다. 실제 선박 성능 수치가 아닙니다.

| 후보 | comb | best_gap | ko_gt_win_best | ko_gt_win_margin |
|---|---:|---:|---:|---:|
| 창 밖 A | .90 | .50 | +.30 | +.30 |
| 창 안 B | .60 | .01 | .00 | +.30 |
| 창 안 C | .30 | .02 | -.30 | -.30 |

코드대로라면 **전체 후보 중 margin 양수는 2개**입니다. “창 안 후보만 놓고 보면 1위만 양수”가 정확합니다. `ko_gt_win_best == 0`도 창 밖 동점 후보를 배제하지 않으므로, 창내 1위 비율을 집계할 때는 `win_mask & isclose(best, 0)`을 써야 합니다.

창 밖 후보에 양수를 주는 정의 자체를 오류로 단정하지는 않습니다. 톤수가 달라도 이름이 매우 맞는 후보를 보존하려는 설계라면 유지할 수 있습니다. 다만 이름이 “창내 지배력”으로 읽히므로 **`ko_in_gt_win`, `ko_gt_win_count` 또는 fallback 표시를 함께 두거나, margin의 창 안/밖 의미를 명확히 문서화**해 주세요. 창 후보가 0개인 fallback, 1개인 경우, 동점도 집계에서 구분하는 편이 좋습니다. 합성 5조건에서는 유한값이 나왔습니다. 실제 추론 오버헤드는 측정하지 않았으므로 “0ms”로 확정하지 않습니다.

## 4. 두 v4-lite 구현은 별도 실험입니다

현재 소스를 정적으로 대조했습니다.

| 항목 | Argon `shared/src/ko_translit_argon_v4.py` | Opus `pinned/build49/ko_translit_argon.py` |
|---|---|---|
| LLM 대응 생성 | 한글/영문 토큰 수가 같은 쌍의 위치별 대응 | 기존 `_count_pairs`의 토큰·DP 부분어·전체 stem 대응 |
| LLM 키 채택 | 빈도≥3·발음≥.58 또는 빈도≥2·발음≥.65 | 발음≥.50, 별도 최소 빈도 조건 없음 |
| LLM 부분어 등록 | 길이·빈도·발음에 추가 제한 | stem 이외 채택 대응을 등록 |

따라서 Argon OOF의 `1136→1148` 등은 해당 harness와 Argon 소스의 결과로만 기록해야 합니다. 메시지에 적힌 “발음≥.65·빈도≥2”도 현재 코드 전체 조건을 요약하지 못합니다. 두 구현을 당장 합치거나 빌드 큐를 바꾸자는 요청은 아닙니다.
