# 항만 ByT5 파일럿 v1

## 실행

1. 같은 Drive 폴더의 `항만_ByT5_파일럿_v1.ipynb`를 Colab으로 엽니다.
2. 런타임 유형을 **L4 또는 A100 GPU**로 바꿉니다. T4도 선택할 수 있으나 float32·작은 배치로 동작하며 속도는 미측정입니다.
3. 위에서부터 실행합니다. Drive 권한을 허용하면 같은 폴더의 ZIP을 자동으로 읽습니다. ZIP을 찾지 못하면 준비된 `port_byt5_pilot_v1.zip`을 직접 선택할 수 있습니다.

학습은 기본 600 optimizer steps입니다. 완료된 학습은 재사용하고, 중단되면 동일 RUN_NAME과 설정으로 마지막 유효 체크포인트부터 이어갑니다. 설정이나 패키지를 바꾸면 새 RUN_NAME을 사용해야 합니다.

기준 모델은 패키지 제작 시 아직 학습 중이어서 포함하지 않았습니다. 기본 설정은 ByT5 학습 후 **코랩 CPU에서 단일 시드 기준선을 생성**합니다. 맥에서 진행 중인 Claude 빌드에는 영향을 주지 않습니다. 기존 전체 학습 33/36 모델을 대신 넣으면 검증 선박을 학습에 사용한 기준선이 되므로 사용하지 않습니다.

## 무엇을 평가하나

- 실제 한글 학습 쌍 269개와 train 역할에서 재선별한 LLM v1 4,867개. 실제/LLM은 각각 전체 샘플링 확률의 50%이며 각 출처 안에서는 선박과 표기별 기여를 나눕니다.
- tune은 실제 한글 61척, 최종 eval은 52척입니다. 학습·조정·평가 선박 및 프롬프트 예시의 교집합을 검사했습니다.
- 원본·오타1/2·자모·절단·단어삭제·어순 변경 7유형을 같은 고정 query로 비교합니다.
- 각 행의 자연 검색 상위 20후보에 정답을 강제로 넣지 않습니다. 후보 누락과 후보 내 선택 오류를 구분합니다.
- ByT5 체크포인트와 결합 가중 선택은 tune만 사용합니다. eval은 결합 기준 고정 후 보고합니다.
- GPU 처리량은 실제 실행한 GPU에서 기록합니다. A100 결과를 L4 속도로 부르지 않습니다.

이것은 **3-way holdout 파일럿**입니다. 전체 5-fold OOF, Public 점수 또는 대회 제출 결과가 아닙니다.

## 결과 위치

`이 Drive 폴더/runs/pilot_v1_s42_600/`

- `training_complete.json`: GPU 학습 완료, 선택 체크포인트, 모델 revision.
- `best/`: 저장된 모델·토크나이저.
- `pilot_report.json`, `metrics.csv`: 기준선·신경망·결합 비교.
- `scoring_manifest.json`: GPU 종류와 실제 처리량.
- `pilot_results.zip`: 분석용 결과 묶음. 이 파일을 Codex에 전달하면 다음 판단이 가능합니다.

## 검증 상태

로컬에서는 데이터 격리·파일 해시·노트북 문법과 작은 무작위 CPU 모델로 손실/학습/점수화/결합 선택을 점검했습니다. 사전학습 ByT5 가중치 로딩, GPU 학습·속도는 아직 실행하지 않았습니다. 로컬 transformers 5.5.0에서 점검했으며 코랩은 대회 환경에 맞춰 4.57.6으로 설치하므로 첫 실행의 환경 점검도 확인해야 합니다.

기술 참고: [ByT5 공식 문서](https://huggingface.co/docs/transformers/model_doc/byt5), [Adafactor 공식 문서](https://huggingface.co/docs/transformers/main_classes/optimizer_schedules).
