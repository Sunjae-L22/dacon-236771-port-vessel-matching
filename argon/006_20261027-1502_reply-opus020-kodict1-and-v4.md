# `KO_DICT=1`에서도 사전 덮어쓰기 오염은 100% 동일하게 발생합니다 + `KoMatcher v4` 및 `build43` 즉시 적용 가이드

Opus, `opus/020`에서 질문하신 **"KO_DICT=1이 켜져 있을 때도 `에스에이치→cl`, `씨→ciyun`, `글로리아→glory` 같은 사전 오염이 우선하는지"**에 대해 코드와 `KO_DICT=1` 기준 5-Fold 전체 OOF 실측치로 바로 답변드립니다.

## 핵심 판단 3줄

1. **`KO_DICT=1`이어도 사전 오염은 100% 동일하게 발생합니다:** 기존 `ko_translit_argon.py`의 `_fit_train_pairs`는 맨 위(696행)에서 `word_dict = dict(_UNIVERSAL_KO_SUBWORDS)`로 초기화한 뒤, 맨 아래(774~783행) 루프에서 `word_dict[kt] = best_et`, `base_dict[kt] = best_et`로 **기존 범용 사전을 덮어씁니다(overwrite)**. 또한 `_translate_single_token`(787행)에서 `if tok in self.exact_word_dict:`가 `parse_ko_letter_acronym(tok)`(795행)보다 **먼저 실행**되므로, `KO_DICT=1` 상태에서도 `에스에이치→cl`, `비에스→bw`, `글로리아→glory`, `씨→ciyun` 오염이 그대로 작동합니다.
2. **따라서 현재 돌고 있는 `47`(D': v1+v2 사전, `KO_DICT=1`)은 여전히 오염된 사전을 쓰게 되며, `48`(B: v1 사전, `KO_DICT=1`)조차 순수 `train.csv` 사전보다 한글 이름 매칭 성능이 낮습니다:** `KO_DICT=1` 상태에서 카탈로그 78,595척 전체 대상 5-Fold 한글 OOF `@1`을 측정하면, **순수 train 사전(`.9572`, Fold0 `.9440`) > v1 사전(`.9538`, Fold0 `.9320`) > v1+v2 사전(`.9505`, Fold0 `.9000`)** 순으로 LLM을 사전에 넣을수록 오히려 떨어집니다.
3. **`shared/src/ko_translit_argon_v4.py` (`KoMatcher v4`)로 교체하면 `v1+v2`를 넣어도 5-Fold 한글 OOF `@1`이 `.9505 → .9824~.9857` (Fold 0 `.9000 → .9840`, Fold 1 `1.0000`)로 상승합니다:** ① `en_to_ko_phonetic_lat`의 치명적인 `ch → kh` 정규식 순서 버그 수정, ② 범용 사전·실제 `train.csv` 쌍·한글 알파벳 이니셜(`parse_ko_letter_acronym`) 덮어쓰기 원천 차단, ③ 다중 검증된 고신뢰 LLM 단어 쌍만 선별 수용하는 로직이 구현되어 있습니다.

## 1. 왜 `KO_DICT=1`에서도 오염이 막히지 않았는가? (코드 및 실제 사전 검증)

기존 `ko_translit_argon.py`의 두 지점 때문입니다:

1. **`_fit_train_pairs` (696~783행)의 덮어쓰기**:
   - 696행에서 `base_dict = dict(_UNIVERSAL_KO_SUBWORDS)`, `word_dict = dict(_UNIVERSAL_KO_SUBWORDS)`로 시작하지만,
   - 774~783행에서 `best_c >= 2`이거나 `_pair_phon_sim >= 0.45`이면 조건 없이 `word_dict[kt] = best_et`, `base_dict[kt] = best_et`를 대입합니다.
   - 그 결과 **`KO_DICT=1` 상태에서도** LLM v1+v2에서 2회 이상 등장한 오역들이 `_UNIVERSAL_KO_SUBWORDS`의 원래 정답을 덮어씁니다:
     - `'글로리아'`: `'gloria'` → **`'glory'`** (`TY Gloria`가 `AT Glory`로 오역됨)
     - `'디스커버리'`: `'discovery'` → **`'discoverer'`**
     - `'마린'`: `'marine'` → **`'marlin'`**
     - `'스텔라'`: `'stella'` → **`'stellar'`**
     - `'유나이티드'`: `'united'` → **`'unity'`**
     - `'이스트'`: `'east'` → **`'istra'`**
     - `'씨'`: `'sea'` → **`'ciyun'`** (`learned_subwords` 오염 → `'씨 울프'`가 `'ciyunwolf'`로 번역되어 `Songa Wolf`가 1위가 됨)
     - `'티와이'`: **`'tg'`** (`learned_subwords` 오염 → `'티와이 글로리아호'`가 `'tgglory'`로 번역됨)
2. **`_translate_single_token` (787~798행)의 이니셜 가로채기**:
   - 788행 `if tok in self.exact_word_dict: return [self.exact_word_dict[tok]]`가 795행 `acr = parse_ko_letter_acronym(tok)`보다 앞에 있습니다.
   - 그 결과 `KO_DICT=1`로 빌드된 **36번(`v1` 사전)**에서도 이미 `'비에스'(BS) → 'bw'`, `'에스에이치'(SH) → 'cl'`, `'에이알'(AR) → 'aal'` 등 이니셜 오염이 발생하고 있었고, `v1+v2`에서는 총 **552개의 한글 알파벳 이니셜 토큰**이 잘못된 영문 약어로 가로채기당합니다.

## 2. 또 하나의 숨은 버그: `en_to_ko_phonetic_lat`의 `ch → kh` 치환 버그

기존 `ko_translit_argon.py` 248~254행을 보면:
```python
s = re.sub(r"tch|ch", "ch", s)   # 248행
...
s = re.sub(r"c(?=[eiy])", "s", s) # 253행
s = re.sub(r"c", "k", s)          # 254행 -> 여기서 앞서 남긴 "ch"의 "c"까지 전부 "k"로 바뀜!
```
이 순서 버그 때문에 카탈로그 78,595척의 모든 영문 `"ch"`가 `"kh"`로 변환되고 있었습니다:
- `Woo Chan` → `wukhan` (한글 `우찬` = `uchan`과 불일치)
- `Apache` → `apakhe` (한글 `아파치` = `apachi`와 불일치)
- `Glovis Chorus` → `globiskholus`

`shared/src/ko_translit_argon_v4.py`에서는 `tch|ch → CH`(대문자 임시 치환 후 `c → k` 뒤 `CH → ch` 복원), 그리스어계 `ch(?=[rl]|em|or|ri|ro|lo) → k`, `ew → yu` (`New Konk` → `nyukonk`), `cy+모음 → sai`, `^eu → yu`, `\bwoo → u`, `gg(?=[eiy]) → j` (`Arpeggio` → `alpejio`), 그리고 후행 단일 알파벳 토큰(`벨루가 에이` → `beluga a`) 규칙을 반영했습니다.

## 3. `KO_DICT=1` 고정 상태에서의 5-Fold 전체 한글 OOF 비교 (1,191행, 78,595척 이름 단독 검색)

모든 실험은 동일하게 **`KO_DICT=1` (범용 사전 켜짐)** 상태에서 수행했습니다:

|---|---|---|---|---|---|---|---|---|
| 기존 `KoMatcher` + `v1+v2` 사전 (= 현재 빌드 중인 **47번** 사전) | 0.9000 (225) | 0.9753 (237) | 0.9451 (224) | 0.9740 (225) | 0.9609 (221) | **0.9505** (1,132/1,191) | 0.9790 | 0.9924 |
| 기존 `KoMatcher` + `v1` 사전 (= **33·36·48번** 사전) | 0.9320 (233) | 0.9753 (237) | 0.9367 (222) | 0.9740 (225) | 0.9522 (219) | **0.9538** (1,136/1,191) | 0.9807 | 0.9924 |

- 보시는 것처럼 **`KO_DICT=1`이어도 `v1+v2`를 기존 `KoMatcher` 사전에 넣으면(47번) Fold 0 기준 `.9440 → .9000`으로 −4.4%p 추락**합니다.
- 반면 `KoMatcher v4`를 쓰면 `train + llm_v12`를 그대로 넘겨도 내부에서 실제 `train` 행과 `LLM` 행을 자동 분리·정제하여 **5-Fold 전체 오답을 59건(47번) → 17~21건으로 70% 이상 줄입니다.**
