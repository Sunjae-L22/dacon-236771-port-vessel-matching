### 왜 `any_tok_postings` 단독(1B)은 `v18`에서 변화가 없었고, 어떻게 해야 작동하는가?
1. **`v3-clean`의 즉각적인 점수 향상은 100% `1C`(단음절 축약 매칭 + 외래어 이질음역)에서 나왔다.**
2. **왜 `KoMatcher.candidates(q, k=40)` 내부의 `any_tok_postings`만으로는 `rename_brand`나 `drop_first_word`의 후보 누락(`(a)`)이 해결되지 않았는가?**
   - `KoMatcher.candidates(q, k=40)`는 **톤수(GT) 정보 없이 카탈로그 전체 78,595척**을 대상으로 검색한다.
   - 예를 들어 `'디에스 오션' -> '우양 오션'`에서 `any_tok_postings["ocean"][:120]`이 정답 `DS Ocean`을 1차 `shortlist`(약 600척)에 넣어주더라도, 최종 반환 시 **전체 문자열 유사도(`ko_combined_score`) 상위 40개(`k=40`)**만 자르기 때문에 카탈로그 내 100여 척의 다른 `* Ocean` 선박들에 밀려 `DS Ocean`(`ko=0.545`, 약 55위)이 `k=40` 밖으로 잘려 나간다!
   - 반대로 `opus_lib.py`의 `query_candidates`는 이미 **`±12%` GT 창(`pool`, 약 300~500척)**을 구해놓고도, 그 안에서는 `KoMatcher` 번역 키(`qinfo["trans"]`, `qinfo["rom_no_eu"]`)가 아닌 **조악한 자음 골격 `ck`(`phon_key`)만 검색**하고 있었다 (`'우양 오션'`의 `ck`는 `"SN"` 2글자뿐이라 GT 창 내 엉뚱한 배들과 매칭됨).

## 4. 해결책 제안 및 Fold 0 검증 결과 (`shared/src/v18_fixes_argon.py`)

오답 유형 1위인 **`(d)` 정답 이름 우위 역전(255건)**과 **`(a)` 후보 미포함(151건)**을 동시에 잡는 **2가지 무위험(Zero-Leakage) 코드 수정**을 설계하고 `v18` 모델 그대로(재학습 없이도 즉시 작동) 검증했어.

### 제안 1 — 후보 검색 수정 (`Fix A`: 유형 `(a)` 오답 **39.0% 즉시 제거**, `105건 → 64건`)
- **`opus_lib.py`의 `query_candidates` 내 `±12%` GT 창(`pool`)에서 `KoMatcher`의 번역 키(`qinfo["trans"]` vs `cat_en_compact`)와 발음 키(`qinfo["rom_no_eu"]` vs `cat_en2ko`)로 `fuzz.ratio` 및 `fuzz.partial_ratio` 상위 `k_ko`개를 추가**:
  - 카탈로그 전체에서는 `'오션'`, `'코랄'`, `'카를로스'`, `'보이저'`가 수십~수백 척이라 `k=40`에서 잘리지만, **`±12%` 톤수 창 안에서는 해당 단어를 가진 배가 1~5척뿐**이므로 `fuzz.partial_ratio`로 100% 포착된다!
- **`meta_candidates`의 톤수 창을 `window=0.06, k=40`에서 `window=0.085, k=60`으로 확대**:
  - 국내 입항 톤수와 국제 총톤수가 6.0%~8.5% 차이 나는 개명·선사교체 선박(`Vostochny Voyager` 8.54% 등)을 후보에 포함시킨다.

### 제안 2 — 그룹 상대 이름 피처 정렬 (`Fix D1`: 유형 `(d)` 오답 **24.0% 즉시 제거**, 원본·어순반전 **1.000 달성**)
- **`opus_lib.py`의 `query_features` 마지막(`if ko and n:` 블록)에서**:
  1. 정방향 점수와 역방향 점수의 최댓값인 **`comb_eff = np.maximum(comb, F[:, col["ko_comb_rev"]])`**로 `ko_combined_score`, `ko_comb_best`, `ko_comb_margin`을 계산한다. (어순이 바뀐 `S4:reorder` 7건 전량 해결: `0.972 → 1.000`)
  2. 한글 쿼리(`if ko:`)의 **`name_best`와 `name_margin`을 구형 `ck_acr_ratio`가 아니라 `comb_eff * 100.0` 기준으로 덮어쓴다**:
     ```python
     comb_eff = np.maximum(comb, F[:, col["ko_comb_rev"]])
     F[:, col["ko_combined_score"]] = comb_eff
     cmax = comb_eff.max()
     csec = np.partition(comb_eff, -2)[-2] if n > 1 else 0.0
     F[:, col["ko_comb_best"]] = comb_eff - cmax
     F[:, col["ko_comb_margin"]] = cmax - csec
     best_ko = comb_eff * 100.0
     bmax = best_ko.max()
     bsec = np.partition(best_ko, -2)[-2] if n > 1 else 0.0
     F[:, col["name_best"]] = best_ko - bmax
     F[:, col["name_margin"]] = bmax - bsec
     ```
  - 이 10줄 수정만으로 **모델 재학습 없이도** `'엠에스 프리지아'`(`MS Freesia` vs `Serene Monaco`)와 `'펭슈하이'`(`Feng Xiu Hai` vs `Feng Shou Hai`)가 모두 해결되어 **`S3:orig` 정확도가 `0.988 → 1.000 (250/250)`**이 된다!
