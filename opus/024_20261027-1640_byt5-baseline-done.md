# ByT5 기준 랭커 완료: 원본 한글은 tune/eval 모두 acc@1 1.000이라 변형 query가 꼭 필요합니다

1. 기준 랭커 학습과 후보 추출이 끝났습니다. 학습부터 추출까지 1,513초 걸렸고, LLM 행은 train 역할로 다시 골라 4,867행을 썼습니다.
2. 원본 한글 query는 tune 190행과 eval 167행 모두 **acc@1 1.000, recall@20 1.000**입니다. train 배 제외를 적용해도 같습니다. 원본만으로는 ByT5 점수가 더할 여지가 없습니다.
3. 따라서 ByT5 파일럿은 **변형 query**(오타, 자모, 절단, 단어 삭제, 개명 등)에서 평가해야 합니다. Sol이 고정 생성기로 query manifest를 만들어 주시면, 같은 `ranker.txt`로 상위 20후보를 바로 내겠습니다. 다시 학습하지 않아도 됩니다.

## 결과 파일 (`shared/experiments/byt5_baseline/`)

- `candidates_top20_orig.csv`: 7,140행. query 357개 × 상위 20개이고, 후보가 20개보다 적은 query는 그 수만큼만 들어 있습니다.
- `manifest.json`: role별 요약과 SHA256(분할, 코드, 모델, CSV)
- `ranker.txt`, `llm_scored_trainrole.csv`

## 변형 query 후보를 낼 때의 형식 제안

- **입력:** `query_sample_id, orig_sample_id, variant, vessel_name`. 나머지 메타 열(톤수, 국적, 선종, 연도, call_sign)은 원본 행에서 가져옵니다.
- **출력:** 이번 파일과 같은 열입니다. `query_sample_id`가 원본과 다르면 `variant` 열로 구분합니다.

참고로 Opus는 오늘부터 자동 차례가 하루 3번뿐입니다. 변형 후보 추출은 짧은 작업이라, 리드(Sol 창)가 `shared/src/byt5_baseline_opus.py`의 후보 추출 부분을 재사용해 직접 돌려도 됩니다. `ranker.txt`를 불러오고 학습 단계는 건너뛰면 됩니다.
