# G1~G3 판정 수용 + 1위 격차에 대한 새 가설 (규칙 위반 가능성)

## 1. 004 수용
- G1·G2·G3와 101 단독 모두 제출하지 않는다. 101은 fold2 순증 −10이라 후보에서 내린다.
- G1에서 확인된 사실이 중요하다. **99의 로컬 변경 90행이 전부 hard였다.** 즉 Public −13은 쉬운 행 훼손이 아니라, test의 hard 행에서 합성 OOF(+12)와 **반대 방향**으로 움직인 결과다. 합성 hard와 test hard가 다르다는 가장 직접적인 증거로 기록한다.

## 2. 새 가설: 1위 0.9891은 test 행 간 call_sign 결합으로 설명된다
train 구조(`data/open/train.csv`):
- call_sign 5,851개 = 선박 5,851척, 1:1 대응
- **한글 행의 93.3%가 같은 call_sign의 다른 행과 함께 있다.** 한글 선박당 평균 3.12행, 같은 배의 한글 행끼리 이름은 모두 같다.
- 영문 행은 71.9%가 2행 이상 그룹에 속한다. 한글 행과 영문 행이 call_sign을 공유하는 경우는 0.3%뿐이다.

test도 같은 방식으로 만들어졌다면 다음이 성립한다.
- 손상된 한글 행 대부분에 같은 call_sign의 다른 test 행이 있다. 그 행이 깨끗하면 정답이 쉽게 나온다.
- 102 기준 hard 약 30%가 거의 전부 풀린다. 그러면 한글 오답 4~8개, 즉 1위 점수와 맞아떨어진다.
- 우리가 합성 손상으로는 hard 행을 개선하지 못하는 현상과도 모순이 없다.

**이 방법은 대회 규칙 위반이다.** 각 test 행은 독립적으로 예측해야 하고, test 행 간 call_sign 그룹화는 금지다. 우리는 쓰지 않는다. 1위가 실제로 이 방법을 쓰는지는 확인할 수 없다. 다만 그렇다면 코드 검증에서 순위가 바뀔 수 있다.

## 3. 전략 함의
- "0.99를 따라가야 한다"는 전제가 틀렸을 가능성이 크다. 규칙을 지키는 팀 사이에서 우리가 몇 위인지가 실제 관심사다.
- 남은 20회의 목표를 바꾼다. Public 과적합을 피하면서 **Private에서도 안전한 최고 후보**를 확정한다. 근거 없는 한글 대수술은 중단한다.
- 기준선 93은 유지한다. 최종 2개 중 하나는 93이다.

## 4. 요청
- [ ] 위 가설에 반대되는 증거가 있으면 제시해 줘. 예: 공식 규칙이나 토크보드에서 test 행 간 정보 사용을 허용한 공지.
- [ ] 규칙을 지키면서 Private에서 기대값이 양수인 저위험 후보가 있다면 1~2개만 제안해 줘. 예: 같은 레시피의 시드를 늘려 분산을 줄이는 것. 79와 93은 이미 6+6모델이다. 근거 없는 제안이면 "없음"으로 답해도 된다.
