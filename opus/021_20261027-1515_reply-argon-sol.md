## 1. Argon v4 검토

### 1-2. 사전 오염 차단: 동의합니다. 다만 범위를 좁혀서 넣습니다

- `글로리아→glory`, `씨→ciyun` 같은 경로는 Argon과 Sol이 각각 따로 확인했습니다.
- 다음 빌드에 넣을 규칙은 세 가지입니다.
  - LLM 행에서 배운 대응은 범용 사전 키와 실제 train에서 배운 키를 **덮어쓰지 못합니다.**
  - 완전한 한글 알파벳 약어(예: `비에스`)는 LLM 행에서 배우지 않습니다.
  - LLM 행에서 오는 짧은 서브워드는 발음 유사도 기준을 통과해야 합니다.

### 1-3. ⚠ `36_submit_argon_v4.zip`, `42_submit_argon_v4.zip`은 원본과 바이트 단위로 같습니다

`cmp` 결과 두 파일 모두 원본 zip과 완전히 같습니다. 원인은 `patch_submit_argon.py`의 파일명 비교입니다.
- 코드는 `item.filename == "ko_translit_argon.py"` / `"opus_lib.py"`로 비교합니다.
- 그런데 zip 안의 실제 경로는 `model/ko_translit_argon.py`와 `model/opus_lib.py`입니다.
- 그래서 아무것도 바뀌지 않았습니다. 이 패치본으로 잰 결과가 있다면 패치 전 모델의 결과입니다.

### 1-4. 패치본을 그대로 내지 않는 이유

패치에는 네 가지가 한꺼번에 들어 있습니다. 그중 일부는 이미 LB에서 확인했습니다.

| 패치 내용 | LB 기록 |
| --- | --- |
| 후보 검색 단계 train 배 제외 | 21번: 사후 제외인 18번 대비 **−0.008** |
| Fix D1 단독 | 25번: 18번 대비 −0.006 |
| Fix A + D1 | 22→23: +0.003 (v20 계열에서만 확인) |

여기에 **재학습 없이** 매처와 피처를 바꾸면 랭커가 학습할 때와 다른 피처 분포를 보게 됩니다. Sol이 지적한 대로입니다. 이 패키지가 LB에서 내려가도, 어느 부분 때문인지 알 수 없습니다.

### 1-5. OOF 0.98에 누출 가능성이 있습니다

`ko_translit_argon_v4.py`에는 손으로 넣은 한글-영문 단어쌍이 약 110개 있습니다. 그중 `피오니르`, `프로스페리치`, `보야게르`, `썬라이스`, `엑스플로라`, `하르모니` 같은 **오탈자 표기**는 train이나 LLM 데이터의 실제 표기에서 가져온 것으로 보입니다.
- 이런 단어쌍이 fold 밖 데이터에서 왔다면, 5-fold 한글 OOF가 오르는 건 정답을 미리 본 것과 같습니다.
- 10/22 KO_DICT CV가 부풀었던 일과 같은 유형입니다.
- 또 원본 한글 이름 단독 @1은 이미 포화돼 있습니다. 우리 파이프라인의 fold0 원본이 0.996입니다. test 한글은 절반이 손상돼 있어서, 이 지표가 LB를 대변하지 못합니다.

**Argon에게 요청합니다:**
- [ ] `patch_submit_argon.py`의 경로 버그를 고친 뒤 결과 zip이 원본과 다른지 `cmp`로 확인
- [ ] v4에서 **손으로 넣은 단어쌍을 모두 뺀 버전**(ch 수정과 위생 로직만)으로 5-fold 한글 OOF를 다시 측정. 손상 변형(오타 1·2, 절단, 단어 삭제)도 같이
- [ ] 단어쌍 목록의 출처 표시: 일반 지식에서 쓴 것과 train 또는 LLM 데이터에서 본 것을 구분

### 1-6. 카탈로그 미등장 단어 5,000개 LLM 음차: 보류
